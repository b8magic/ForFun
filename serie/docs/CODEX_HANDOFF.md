## Current update: Serie 1.3.0

Implementation follows the user's next iPhone feedback: compact numeric duration entry, fewer redundant labels, consistent year typography, smaller activity pills, dismissible save messages, native status-bar scroll correction, inline monthly history details and editing existing sessions together from Home.

- Home uses explicit **Nuove / Modifica** modes. New logging drafts remain separate and durable; existing-session selection is transient and contains stable session IDs. Tapping a day with multiple sessions opens an individual checklist, so other activities and unselected same-day sessions cannot be changed accidentally. Empty days are disabled in edit mode.
- Bulk details use independent **Mantieni / Imposta / Rimuovi** operations for notes, place and timing. All selected records and their complete versions are checked before one SQLite transaction writes any changes. Every target date validates its own wall time/DST result. Stale/missing/moved records or invalid dates reject the entire batch. Untouched details, including exact seconds, remain intact. The export lock orders edits after already-running exports; no bulk operation silently rewrites existing calendar events or schedules new exports.
- Applying selection details still updates only the activity's persistent new-session draft. Home **Salva** creates the sessions; bulk **Salva modifiche** updates already-existing sessions immediately. Cancel/discard does neither.
- One numeric duration input formats `1237` as `12h37m`, supports numeric typing, backspace, range edits and pasted colon/unit forms, and preserves saved second precision until the duration itself is edited. Notes have no instructional placeholder; optional/declared-duration repetitions are removed.
- Save confirmations move with a drag in any direction. A completed drag dismisses only the message, never its sessions. A short/cancelled drag springs back and restores keyboard/accessibility activation; an intentional **Annulla** tap retains existing undo behavior. Outgoing toast handlers cannot dismiss replacement messages.
- Month history expands one day panel beneath its month, with timing, place and a bounded first note line. Selecting another day updates that inline panel; session edits return to the same selected day/filter/scroll. Deletion still requires confirmation. Year drill-down focuses the selected month, where dates use the same inline panel; Home and period details retain the full day sheet.
- The year now uses exactly the same condensed typeface as month headings. Activity pills are visually smaller with 44pt minimum touch targets. Both Home scroll views disable UIKit's automatic scroll-to-top shortcut, which otherwise targets the virtual calendar's first month (January 1900).

No dependencies or database schema changes are required. The existing six-table native migration gate remains in place. Linux checks cover the data, timing and actual browser UI; the coordinated candidate workflow will additionally compile and execute the native Release app before producing a single unsigned IPA. Unlike the previous IPA-only delivery, this update includes a fifth native flow for status-bar taps, numeric keyboard entry, message swipes, inline history and bulk editing. Standard hosted runners on the now-public repository do not consume the private-repository included-minute allowance.

## Main decisions

The user-facing Italian decision register is [DECISIONI.md](DECISIONI.md). It records the recommended choices that can be revisited after device testing, without blocking the single-version delivery.

Home uses a continuous shared calendar with visible activity chips, a sticky month jump, a cream default and a saved dark option. The persistent activity dock and Storia header provide the primary navigation. Full and reduced motion use the same compact layout: waves stay local and date hit targets hold their positions. Day markers are derived from actual session/category contributions; the all/active marker preference changes visibility, never stored sessions. Glyphs show up to four colors plus +N overflow, with every contribution retained in labels/day details. Geometry allocates equal shares to distinct activities; session volume is expressed by recorded counts. Motion defaults to the system accessibility preference. Activity, period and saved-session editors share dirty-form protection for Close/back and native sheet gestures.

Drafts are persisted per stable activity id with dates, applied optional details and a retry-safe request id. Selection-details edits remain local until Applica; closing that panel discards unapplied edits while preserving the previously applied draft. Switch/restart restores each draft; successful save clears only its captured draft. Draft/activity removal cannot leak stale data into another activity.

Main-calendar tap selects a date for logging. Long press or the explicit one-selected-day detail action opens the full actual day across activities. Existing session editing returns to that day, then to its origin. **Nuova sessione** selects the date; it does not save automatically.

History shares month/day drawing, opens populated month calendars immediately, shows twelve small calendars in populated years, disables empty/future year drill-down and uses **Progressi** for all-time analysis. Month history omits empty month rows; year placeholders, filter zeros and unknown durations stay explicit.

Named periods are inclusive metadata filters over actual sessions, using all or selected stable activity ids. Duplicate names/overlap/future endpoints are allowed. Metadata deletion never deletes sessions. Activity, period and saved-session editors share dismissal guards; theme subscriptions apply across functional sheets.

Calendar providers/engines remain intact. A separate memory-provider web bundle is used only for automated integration checks. The final release pipeline pins one SHA through Linux gates → native simulator smoke → unsigned IPA; normal development pushes cannot trigger it. Standalone manual IPA dispatch and the 1.2 IPA-only marker build artifacts only; publication requires the candidate path. The 1.2 delivery uses local verification plus IPA compilation and does not claim the simulator gate. IPA assets include SHA-256 and `Serie-build.json` source/run/app-version provenance; the app version is read from the built native Info.plist and appears in the release title/body. Release tags use globally unique `ipa-<run_id>` identifiers so the new candidate workflow's run-number counter cannot overwrite an original IPA release.
